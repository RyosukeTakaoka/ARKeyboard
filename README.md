# ARKeyboard — 膝(または机)をキーボードにする iPhone アプリ

iPhone の背面カメラで両手の指先を追跡し、iPad の分割キーボードのような配置で
「指で面を叩いた瞬間」を1文字の入力にするアプリです。
研究(TouchInsight、Acustico、Goodman ら、Gunawardana ら など)の考え方を、
iPhone の標準フレームワークで実現できる範囲で取り入れています。

- 対象: iPhone 実機、iOS 17 以上、SwiftUI
- 外部ライブラリ: なし(MediaPipe は任意。入れなくてもビルド・動作します)
- 手・音・動きのデータは端末の外に送信しません

> このファイルは作業の途中経過です。最終版は作業の最後に更新します。

## 1. 実機での実行手順

### 必要なもの
- Mac(Xcode 16 以上。このプロジェクトは Xcode 16 の「フォルダ同期」形式です)
- iPhone(iOS 17 以上)と USB ケーブル
- Apple ID(無料のものでも実機で動かせます)

### 手順
1. Mac でこのリポジトリをクローンし、**`ARKeyboard.xcodeproj` をダブルクリック**して Xcode で開きます。
   (同じフォルダにある `Package.swift` はロジックのテスト用です。アプリは .xcodeproj から開いてください)
2. 左のナビゲーターで一番上の「ARKeyboard」(青いアイコン)を選び、TARGETS の「ARKeyboard」→
   **Signing & Capabilities** を開きます。
   - **Team** で自分の Apple ID(Personal Team)を選びます。
   - **Bundle Identifier** の `com.example.ARKeyboard` を、自分だけの名前(例: `com.あなたの名前.ARKeyboard`)に変えます。
     (`com.example` のままだと、他の人と重なって署名に失敗することがあります)
3. iPhone を Mac につなぎ、Xcode 上部の実行先で自分の iPhone を選びます。
   - 初めての場合、iPhone の **設定 → プライバシーとセキュリティ → デベロッパモード** をオンにして再起動が必要です。
4. ▶︎(Run)ボタンを押します。
   - 初回は iPhone 側で「信頼されていないデベロッパ」と出ることがあります。
     **設定 → 一般 → VPN とデバイス管理** で自分の Apple ID を「信頼」してください。
5. アプリが起動したら、許可のダイアログで次を許可します。
   - **カメラ**(必須): 指先の追跡に使います
   - **マイク**(推奨): 叩いた音で、タップの判定を正確にします(許可しなくてもカメラだけで動きます)
   - モーション(机モードで「本体の振動」を使うときだけ)

### コマンドラインでのビルド確認(任意)
```sh
xcodebuild -project ARKeyboard.xcodeproj -scheme ARKeyboard \
  -destination 'generic/platform=iOS' -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

### シミュレーターでは?
シミュレーターにはカメラが無いため、「実機で実行してください」と表示されます(クラッシュはしません)。

## 2. 使い方

1. **iPhone の置き方**: iPhone を手の上にかざすように固定し、背面カメラで両手が画面に収まるようにします
   (画面は自分の方を向く)。スタンドやアームで固定するのがおすすめです。
2. 画面下の **「キャリブレーション」** を押し、両手をホームポジション
   (左: A S D F、右: J K L ;。親指はスペース)に置いて **2秒静止** します。
3. 半透明のキー配置が表示され、指先の下のキーが光ります。指で面を「トン」と叩くと入力されます。
4. 画面下のボタン:
   - スライダー: 感度(右ほど小さなタップにも反応)
   - 赤い丸: 記録モード(評価用のデータを集める)
   - 帽子: 練習モード(お題・正解率・速さ)
   - てんとう虫: デバッグ表示(速度グラフ・音の波形・FPS・タップログ)
   - 歯車: 設定(膝/机モード、しきい値、デコーダー、センサー、LiDAR など)

### 膝モードと机モード
| | 膝モード | 机モード |
|---|---|---|
| キーの大きさ | 1.15 倍 | 1.0 倍 |
| キー配置の基準 | 手に追従(脚が動いてもずれにくい) | 面に固定(実物のキーボードに近い) |
| タップの判定 | ゆるめ(布や脚はやわらかく止まり方がゆるい) | 厳しめ |
| 四隅の登録(ホモグラフィー) | 使わない(膝は平らでない) | 使える(奥が小さく映るゆがみを直す) |

## 3. うまく動かない時の確認項目

| 症状 | 確認すること |
|---|---|
| 「実機で実行してください」と出る | シミュレーターで動かしていないか |
| 「カメラへのアクセスが許可されていません」 | 設定アプリ → ARKeyboard → カメラ をオン |
| 手の骨格(点と線)が出ない | 明るい場所か/手が画面に入っているか/手のひらを下にしているか |
| 左右の色が逆(左手がオレンジ) | 設定 → キー配置 → 「左右の手を入れ替える」 |
| キャリブレーションが終わらない | 両手の指先がすべて見えているか(案内の文を確認)/2秒間動かさない |
| キーの位置がずれていく | 机モードなら iPhone や机が動いていないか(動いたら再キャリブレーション)/膝モードは「手に追従」 |
| 叩いても入力されない | デバッグ表示のタップログを見る。「音なし」なら設定のマイクの状態・音の感度 k・時間窓を確認。ログに何も出ないなら感度を上げる |
| 叩いていないのに入力される | 感度を下げる/「音の立ち上がりを条件にする」をオン |
| 同じ文字が2回入る | クールダウンを長く |
| 隣のキーになる | 再キャリブレーション/キーの大きさ/「指の担当キーだけから選ぶ」をオン |
| 触覚が来ない | 設定 → フィードバック/iPhone 本体の「サウンドと触覚」 |
| FPS が低い(20 未満) | 明るい場所で使う/ほかのアプリを閉じる/デバッグ表示を切る |

## 4. タップ判定のしきい値の調整方法

タップは「指先が**手のひらに対して**素早く下りて(手首の方向へ動いて)、**急に止まった**瞬間」です。
加えて(マイクを使う場合)、その前後に**叩いた音**があることを条件にします。

### 手順
1. 画面下のてんとう虫でデバッグ表示を出し、グラフのメニューで調整したい指(例: 右手の人差し指)を選びます。
2. その指で何回か叩き、グラフを見ます。
   - **白い線** = 下向きの速さ、**赤い点線** = しきい値、**黄色の点** = 下ろし中、**緑の縦線** = タップと判定
3. 状況に応じて調整します(設定 → タップ判定):

| 見えている状態 | 調整 |
|---|---|
| 叩いても白い線が赤い点線を超えない | 感度を上げる、または「下ろす速さのしきい値」を下げる |
| 黄色の点は出るのに緑の線が出ない(止まりを検出できない) | 「止まりの判定(ピーク比)」を上げる/「平滑化」を下げる |
| 指を動かしただけで緑の線が出る | 感度を下げる/「最小の移動量」を上げる/音の条件をオン |
| 1回で2回入る | 「クールダウン」を長く |
| 隣の指がつられて入る | 「同じ手の別の指のロック」を長く |
| 手ごと動かすと入る | 「手全体の動きの上限」を下げる |

4. 音の条件(レベルA)の調整: タップログの「音±○ms」を見て、ほとんどが時間窓(初期値 −100〜+60ms)に
   入るよう設定 → センサーと二重条件 の時間窓を合わせます。音の波形グラフでは、赤い縦線(音)と
   緑の縦線(カメラのタップ)が近くに並んでいれば正常です。

すべての初期値は `ARKeyboard/Core/KeyboardSettings.swift` の `applyModeDefaults` にまとめてあります。

## 5. 記録と評価(データで比べる)

「機能を足したら本当に良くなったか」を数字で比べるための仕組みです。

1. **記録**: 画面下の赤い丸 → 課題を選ぶ → 表示された文字を打つ。
   関節の座標・音の特徴・加速度・目標の文字が JSON で保存されます(映像は保存しません)。
2. **Mac へ送る**: 設定 → 記録データ → 共有ボタン(AirDrop)、または「ファイル」アプリ → このiPhone内 → ARKeyboard → Recordings。
   リポジトリの `recordings/` フォルダに置きます。
3. **評価**(Mac のターミナルで、リポジトリのルートで):
   ```sh
   swift build -c release --product arkeyboard-replay   # 初回だけ
   python3 tools/eval/evaluate.py recordings/*.json      # docs/results.md ができる
   python3 tools/eval/evaluate.py --synthetic            # 記録が無いときの動作確認(合成データ)
   ```
   再生コマンドは、アプリと**同じ Swift のコード**で記録を判定し直すので、評価とアプリの動きが一致します。
4. ロジックの単体テスト: `swift test`(Mac のターミナルで。iPhone が無くても実行できます)

現在の `docs/results.md` は**合成データ**による結果です(実際の性能ではありません)。

## 6. 仕組みの概要とファイル構成

```
カメラ(AVFoundation / LiDAR機は ARKit)
  → 手の追跡(HandTracker: Vision。MediaPipe も差し替え可能)
  → 左右の割り当て・手の座標系(HandFrame)・机モードはホモグラフィー
  → キャリブレーション(Calibrator)・キー配置(KeyLayout)
  → タップ候補(TapDetector: 相対速度 + 急停止)
  → センサー融合(SensorFusion: 音のオンセット・振動・LiDAR)= タップ推定レベルA
  → TouchEvent(いつ・どの指・どこ・確からしさ)
  → デコーダー(TapDecoder: 空間タッチモデル × 指の制約 × 文字 n-gram、アンカー)
  → 入力・触覚・音・記録
```

| フォルダ | 内容 |
|---|---|
| `ARKeyboard/Core/` | 画面にもカメラにも依存しないロジック(`swift test` でテスト可能) |
| `ARKeyboard/Camera/` | カメラ・手の追跡(AVFoundation, Vision, ARKit) |
| `ARKeyboard/Sensors/` | マイク(AVAudioEngine + Accelerate)・加速度(CoreMotion) |
| `ARKeyboard/ViewModel/` | 画面とロジックの橋渡し、保存、触覚・音 |
| `ARKeyboard/Views/` | SwiftUI の画面 |
| `ARKeyboard/Resources/Corpus/` | 言語モデルの学習用テキスト(このリポジトリのために自作) |
| `Tests/ARKeyboardCoreTests/` | 単体テスト |
| `tools/replay/` | 記録の再生コマンド(Swift) |
| `tools/eval/` | 評価ツール(Python) |
| `tools/lm/` | 言語モデルの Python 参照実装 |
| `docs/research/` | 論文・資料の調査メモと実現可能性の判断 |
| `docs/results.md` | 評価結果(自動生成) |

### 言語モデルの学習データの出所
`ARKeyboard/Resources/Corpus/corpus_english.txt` と `corpus_romaji.txt` は、
**このリポジトリのために新しく書いた文章**です(既存の文章の転載ではないので、著作権の問題はありません)。
規模が小さい(英語 約7千文字、ローマ字 約4.5千文字)ため、大きなコーパスに比べると予測は弱めです。

## 7. 置いた仮定

(作業の最後に、すべての仮定をここにまとめます。主なもの)

- iPhone を手の上にかざし、背面カメラで手の甲側(手のひらを下)を見る置き方を想定。
  この置き方では、指を下ろすと指先は画像上で「手首の方向」に動いて見えるので、タップの向きの初期値を「手首の方向」にした。
- 画面は縦向き固定。背面カメラの画像は `.right` の向きとして Vision に渡す。
- カメラの撮影時刻(CMSampleBuffer の時刻)、マイクの時刻(AVAudioTime の hostTime)、
  CoreMotion の時刻は、すべて「端末起動からの秒数」で同じ基準と仮定(実機での確認が必要)。
- しきい値の初期値は、合成データと一般的な指の動きの速さからの推定。実機で調整が必要。
